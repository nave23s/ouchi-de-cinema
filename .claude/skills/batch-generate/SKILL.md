# バッチ生成スキル(10本単位・マスター照合つき)

**CLAUDE.mdの作業フロー(調査→計画提示→承認待ち→実装→サンプル確認→コミット→報告)を厳守すること。**

## Step 0: 構造確認(毎回必須)

1. リポジトリルートの `movies.json` を確認(件数・フィールド構造)
2. `data/masters/` の composers.json / artists.json / genres.json の存在を確認
3. ページ出力先ディレクトリとテンプレートの場所を確認
4. **このスキルの記述と実構造に食い違いがあれば、作業を止めてユーザーに報告する**

マスターファイルが存在しない場合は、backfill-data スキルの「マスター初期化」を先に実行するよう案内する。

## Step 1: 未生成レビューの抽出

movies.json から `d`（レビュー本文）が空、または `review_generated` が未設定・false のエントリーを最大10本リストアップし、ユーザーに提示して承認を得る。

**除外ルール**: Type B(レガシー数値URL)・Type C(手書き6ページ)に該当するエントリーは対象外。除外した場合はスキップログを提示する。

## Step 2: マスター照合(生成前)

対象10本の composer / artists / genre がマスターに存在するか照合する。

- マスターにない名前 → 表記ゆれか新規かを判定し、新規ならマスター追加を提案(承認後に追加)
- ジャンルは genres.json の固定リスト以外を使わない

## Step 3: 10本分を1回のAI呼び出しで生成

以下の形式で **1回で10本** 生成する(10本超は品質低下のため禁止):

```
以下10本の映画について、それぞれJSON形式でレビューを生成してください。

[映画リスト: タイトル/年/監督/作曲家/主題歌アーティスト/ジャンル]

各映画の出力形式:
{
  "slug": "...",
  "catchphrase": "(1行。感覚的なキャッチフレーズ)",
  "verdict": "(冒頭掲載用の結論。この映画の音の価値を1〜2文で断言する)",
  "review": "(250〜350字。主観的レビュー。音・音楽への言及必須。結論を最初の1文に)",
  "sound_description": "(200字。音楽・音響の解説。作曲家名を必ず含める)",
  "faq": [
    {"q": "『(タイトル)』の音楽の聴きどころは?", "a": "(50〜80字で断言形式)"},
    {"q": "『(タイトル)』はどんな人におすすめ?", "a": "(50〜80字)"}
  ],
  "seo_title": "(32字以内)",
  "seo_description": "(100字以内。冒頭に結論)"
}

全体の出力: {"results": [...10件の配列...]}
```

**AIO対応の理由**: 冒頭結論・断言形式・FAQ構造はAI検索での引用率を高める。曖昧表現(「〜かもしれない」)は使わない。

## Step 4: 検証(コミット前に必須)

- [ ] ID / slug の重複がないか(movies.json全体と突合)
- [ ] マスター外の作曲家名・アーティスト名・ジャンルが混入していないか
- [ ] 各レビューに音楽への言及があるか
- [ ] 既存の生成済みレビューを上書きしていないか(`d` フィールドに値があるエントリーは絶対に上書き禁止)

## Step 5: ページ生成とサンプル確認

テンプレートから静的ページを生成し、**3ページ分のサンプルをユーザーに提示**して確認を受ける。

## Step 6: コミット(承認後のみ)

コミットメッセージ例: 「レビュー10本追加(バッチ生成)」。push は報告と承認の後。

## コスト目安

1バッチ(10本): 約$0.01 / 未生成分の残数を毎回報告すること。
