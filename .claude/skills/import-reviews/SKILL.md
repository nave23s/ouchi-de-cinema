# レビューインポートスキル（コロン区切り方式 / Google Forms CSV）

**CLAUDE.mdの作業フローを厳守。既存エントリーの上書きは絶対禁止。ユーザーが書いたレビュー本文は一字も変更しない。**

---

## 入力フォーマット（現行・コロン区切り方式）

Googleフォームの「レビュー本文」欄に以下の形式で入力する。

```
タイトル：ロッカーズ
公開年：2003
監督：井筒和幸
劇伴：山本圭蔵
テーマ曲：Various Artists
ジャンル：コメディ、音楽、青春
---
ここにレビュー本文を書く。
コロン（：）が含まれても本文として扱う。
映画『ロッカーズ』は〜のように書いてもOK。
```

「区分」はフォームの別選択欄（ラジオボタン）で指定する。本文内には書かない。

複数レビューを1回の送信に含める場合は `===`（3文字以上）で区切る：

```
タイトル：映画A
公開年：2022
---
本文A

===

タイトル：映画B
公開年：2021
---
本文B
```

### 必須項目

| 項目 | 取得元 | バリデーション |
|------|--------|-------------|
| タイトル | 本文欄のメタブロック | 空はエラー |
| 公開年 | 本文欄のメタブロック | 4桁数値以外はエラー（「2021年」は自動補正） |
| 区分 | フォームの選択欄（列名「区分」） | 「映画」「別館」以外はエラー |

### 任意項目（省略可・後でbackfill可）

監督 / 劇伴（作曲家） / テーマ曲（主題歌） / ジャンル

---

## auto-detect（3方式の切り分け）

CSVのヘッダー行の列名で判定する：

| 条件 | 方式 |
|------|------|
| 「区分」列がある | **現行コロン方式**（このドキュメントの主処理） |
| 「映画タイトル」列がある | **旧9列方式**（後述・後方互換） |
| 上記以外 + 本文に `【タイトル】` を含む | **旧ヘッダー方式**（後述・後方互換） |

---

## Step 0: 構造確認とCSV特定

1. movies.json の現在の件数と最大の n 値を確認
2. annex.json の現在の件数を確認
3. data/masters/ の3マスターを読み込む
4. CSVファイルの場所を確認（プロジェクト直下の「フォームの回答」を含むCSV）
5. CSVヘッダー行を読み、上記auto-detect判定で方式を確定する

---

## Step 1: パースと正規化（コロン方式）

### メタブロックのパース手順

1. CSVから「本文」列と「区分」列を取得
2. 本文セル全体を `\n===+\n` でsplit → 複数エントリのリスト
3. 各エントリを**最初の** `\n---` でsplit → 上=メタブロック、下=本文
4. メタブロックの各行を最初のコロン（全角`：`または半角`:`）で分割 → `キー: 値`

### タイトル抽出（優先順位）

1. メタ行に `タイトル：値` 形式の行がある → その値を使用
2. メタブロック内に `『〜』` パターンの行がある → `『』`内をタイトルとして抽出（空白を除去）
3. 両方なし → エラー停止

### 項目名マッピング（表記ゆれ吸収）

| 入力キー（例） | 変換先フィールド |
|-------------|--------------|
| タイトル / 題名 / 作品名 | `title` |
| 公開年 / 年 / リリース年 | `year` |
| 監督 | `director` |
| 劇伴 / 音楽 / 作曲家 / 作曲 / スコア | `composer` |
| テーマ曲 / 主題歌 / 挿入歌 / テーマ | `artists` |
| ジャンル / 分類 | `genre` |
| 主演 / 出演 / キャスト / その他 | **無視**（警告ログに記録のみ） |

### 正規化

- タイトル前後の空白除去（`『 ロッカーズ 』` → `ロッカーズ`）
- 公開年は `/(\d{4})/` で4桁数値のみ抽出（「2003年」→ 2003）
- ジャンルはスラッシュ `/`・カンマ `,`・読点 `、` で区切り配列化。中黒（・）は区切らない（「時代劇・歴史」はマスター内の1ジャンル）
  ```
  parseGenre: raw.split(/[\/,、]/).map(s => s.trim()).filter(Boolean)
  ```
- テーマ曲は「アーティスト名 / 曲名」形式を分解（形式外はそのまま保持してログ）

### バリデーション（エラー停止）

```
タイトル → 取得できない場合はエラー
公開年   → 未記入または4桁数値が取れない場合はエラー
区分     → 未記入、または「映画」「別館」以外の値はエラー
本文     → 空またはスペースのみはエラー
```

エラー行は「エラーリスト」として一覧提示し、その行をスキップして残りを続行。
0件通過の場合は全体停止。

### 補助警告（エラーにしない）

区分=「映画」なのに以下を含む場合、プレビューに注記：
- タイトルまたは本文に「Season」「シーズン」「第\d+話」「S\dE\d」「連続ドラマ」「ドラマシリーズ」「TVアニメ」

---

## Step 2: 重複チェック（必須）

### インポート済み確認

`data/import-log.json` の `processed` 配列を検索し、`"key": "タイトル_公開年"` が存在すれば再取り込みスキップ。

### 重複チェック対象

| 区分 | チェック対象 |
|------|-----------|
| 映画 | movies.json + annex.json の両方 |
| 別館 | annex.json + movies.json の両方 |

一致・類似が見つかった行は自動追加せず「重複疑いリスト」として提示し、ユーザー判断を仰ぐ。

---

## Step 3: マスター照合

- 作曲家・アーティスト名をマスターと照合。表記ゆれはマスター表記に統一を提案
- 新規の名前はマスター追加案（slug付き）を提示し、承認後に追加
- ジャンルは genres.json のリスト外の値を検出したら報告（勝手に追加しない）

---

## Step 4: プレビューと承認

追加予定エントリーを表形式で提示：

| タイトル | 年 | 区分 | 監督 | 作曲家 | 主題歌 | ジャンル | レビュー冒頭30字 |

あわせて報告する：
- 追加 ◯件 / 重複疑い ◯件 / エラー行 ◯件 / スキップ（インポート済） ◯件
- マスター新規追加 ◯件
- 警告（シリーズ疑い） ◯件

**ユーザー承認まで movies.json / annex.json には書き込まない。**

---

## Step 5: 書き込み

### 振り分け先

- 区分=「映画」→ movies.json に追加
- 区分=「別館」→ annex.json に追加

### n の採番

movies.json行き・annex.json行きともに `max(movies.json最大n, annex.json最大n) + 1` から連番（n空間を共有して衝突を防ぐ）

### フィールド書き込み

- レビュー本文 → `d` フィールドへ（原文のまま、一字も変更しない）
- 新フィールド（director / genre / music 等）はCLAUDE.mdの対応表に従う
- `slug` は付けない（未公開状態。ページ生成は batch-generate で別途実行）
- `s: false` をデフォルトとして設定

### import-log.json の更新

`processed` 配列に追記する形式：

```json
{ "key": "ロッカーズ_2003", "n": 2980, "dest": "movies", "imported_at": "2026-07-12" }
```

## Step 6: コミット（承認後のみ）

コミットメッセージ例：「フォームレビュー◯件インポート（映画◯件・別館◯件）」。push は報告後。

---

## 旧形式パース（後方互換・移行期のみ）

### 旧ヘッダー方式（【タイトル】形式）

auto-detectで「本文に`【タイトル】`を含む」と判定された場合に使用。
`【キー】値` 形式でメタをパース。`---` より上のみを対象にする。
区分は `【区分】` ヘッダーから取得（この方式のみ本文内に区分を書く）。

Step 2〜6は現行コロン方式と共通処理。

将来削除予定：新フォームへの移行が安定した後に旧ヘッダー方式のコードを削除する。

### 旧9列方式（旧フォームCSV）

CSVヘッダーに「映画タイトル」列がある場合に使用。

想定列：タイムスタンプ / 映画タイトル / 公開年 / レビュー本文 / 監督 / 作曲家(劇伴) / 主題歌・挿入歌 / ジャンル / 備考

- タイムスタンプで `data/import-log.json` の `legacy_timestamps` と照合し、処理済みをスキップ
- 区分列がないため、デフォルトで「映画」扱いとし、プレビューで明示する
- Step 2〜6は現行コロン方式と共通処理

将来削除予定：旧フォームのデータが完全に取り込まれた後に削除する。
