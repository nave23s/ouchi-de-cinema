# レビューインポートスキル（ヘッダー方式 / Google Forms CSV）

**CLAUDE.mdの作業フローを厳守。既存エントリーの上書きは絶対禁止。ユーザーが書いたレビュー本文は一字も変更しない。**

---

## 入力フォーマット（新形式）

Googleフォームの「レビュー本文」欄に以下の形式で入力する。

```
【タイトル】インセプション
【公開年】2010
【監督】クリストファー・ノーラン
【作曲家】ハンス・ジマー
【主題歌】（省略可・行ごと省略でOK）
【ジャンル】SF/アクション
【区分】映画
---
レビュー本文をここに書く。
---より上の内容は本文に含まれない。複数行OK。
```

複数レビューを1回の送信に含める場合は `===`（3文字以上）で区切る：

```
【タイトル】映画A
...
---
レビューAの本文

===

【タイトル】映画B
...
---
レビューBの本文
```

### 必須ヘッダー（3つ・欠けたらエラー停止）

| ヘッダー | 値 | バリデーション |
|--------|---|------------|
| 【タイトル】 | 映画タイトル | 空はエラー |
| 【公開年】 | 4桁数値 | 数値以外はエラー（「2021年」は自動補正） |
| 【区分】 | 「映画」または「別館」 | それ以外の値・未記入はエラー |

**【区分】にデフォルト値はない。必ず明記すること。**

### 任意ヘッダー（省略可・後でbackfill可）

- 【監督】【作曲家】【主題歌】【ジャンル】

### 本文（---以降）

- 空またはスペースのみはエラー停止（空エントリの量産を防ぐ）

---

## auto-detect（移行期）

CSVの本文欄に `【タイトル】` が含まれていれば **新形式**（ヘッダーパース）として処理する。
含まれていなければ **旧形式**（9列CSVパース）として処理する（後述）。

---

## Step 0: 構造確認とCSV特定

1. movies.json の現在の件数と最大の n 値を確認
2. annex.json の現在の件数を確認
3. data/masters/ の3マスターを読み込む
4. CSVファイルの場所を確認（プロジェクト直下の「フォームの回答」を含むCSV）
5. 先頭数行を表示して新形式か旧形式かを判定する

---

## Step 1: パースと正規化

### 新形式パース手順

1. CSVの本文列を取得（列名「レビュー本文」またはその前後）
2. セル全体を `\n===+\n`（改行＋3つ以上のイコール＋改行）でsplit → 複数エントリのリスト
3. 各エントリを **最初の** `\n---` でsplit → 上=ヘッダーブロック、下=本文
4. ヘッダーブロックを行ごとに処理：`【キー】値` の形式を抽出（1行に複数【】がある場合は最初の値のみ使用）
5. 本文（---以降）を取得

### 誤爆防止ルール

- `【】` のパースは **ヘッダーブロック（---より上）のみ**。本文中の`【】`は無視する
- 区切り判定は最初の `---` のみ（本文中の `---` はMarkdownとして扱い無視）
- `===` による分割は `\n===+\n` パターンのみ（本文内の `===` は行頭でなければ誤爆しにくい）
- ヘッダーキーは全角【】のみ受け付ける。半角`[]`は警告ログに記録してスキップ

### 正規化

- 【タイトル】前後の空白除去
- 【公開年】は `/(\d{4})/` で4桁数値のみ抽出（「2021年」→ 2021）
- 【ジャンル】はスラッシュ（/）またはカンマ（,）で区切り配列化。中黒（・）は区切らない（「時代劇・歴史」はマスター内の1ジャンル）。番号付き（「3. ドラマ」→「ドラマ」）を除去
- 【主題歌】は「アーティスト名 / 曲名」形式を分解（形式外はそのまま保持してログ）
- 人名の長音符抜け（「ブリュワ」→「ブリュワー」等）は確認できる場合のみ補正を提案

### バリデーション（エラー停止）

```
【タイトル】 → 空ならエラー
【公開年】   → 未記入または4桁数値が取れない場合はエラー
【区分】     → 未記入、または「映画」「別館」以外の値はエラー
本文         → 空またはスペースのみはエラー
```

エラー行は「エラーリスト」として一覧提示し、その行をスキップして残りを続行する
（エラー1件で全体を止めない。ただし0件通過の場合は全体停止）

### 補助警告（エラーにしない）

【区分】=「映画」なのに以下を含む場合、警告として出力してプレビューに注記する：
- タイトルまたは本文に「Season」「シーズン」「第\d+話」「S\dE\d」「連続ドラマ」「ドラマシリーズ」「TVアニメ」「テレビアニメ」

---

## Step 2: 重複チェック（必須）

### インポート済み確認

`data/import-log.json` の `processed` 配列を検索し、`"key": "タイトル_公開年"` が存在すれば再取り込みスキップ。

### 重複チェック対象

| 区分 | チェック対象 |
|-----|-----------|
| 映画 | movies.json + annex.json の両方 |
| 別館 | annex.json + movies.json の両方 |

両方をクロスチェックする理由：誤配置・移動漏れの検出。

### 比較方法

1. タイトル完全一致（空白・全半角を正規化して比較）
2. タイトル類似（部分一致・表記ゆれ疑い）＋ 公開年が近い場合

一致・類似が見つかった行は自動追加せず「重複疑いリスト」として提示し、ユーザー判断を仰ぐ（スキップ / 別作品として追加 / 既存を更新）。

---

## Step 3: マスター照合

- 作曲家・アーティスト名をマスターと照合。表記ゆれはマスター表記に統一を提案
- 新規の名前はマスター追加案（slug付き）を提示し、承認後に追加
- ジャンルは genres.json のリスト外の値を検出したら報告（勝手に追加しない）

---

## Step 4: プレビューと承認

追加予定エントリーを表形式で提示：

| タイトル | 年 | 区分 | 監督 | 作曲家 | 主題歌 | ジャンル | レビュー冒頭30字 |

あわせて報告する：
- 追加 ◯件 / 重複疑い ◯件 / エラー行 ◯件 / スキップ（インポート済） ◯件
- マスター新規追加 ◯件
- 警告（シリーズ疑い） ◯件

**ユーザー承認まで movies.json / annex.json には書き込まない。**

---

## Step 5: 書き込み

### 振り分け先

- 【区分】=「映画」→ movies.json に追加
- 【区分】=「別館」→ annex.json に追加

### n の採番

- movies.json行き：movies.json の最大n + 1から連番
- annex.json行き：max(movies.json最大n, annex.json最大n) + 1から連番（n空間を共有して衝突を防ぐ）

### フィールド書き込み

- レビュー本文 → `d` フィールドへ（原文のまま、一字も変更しない）
- 新フィールド（director / genre / music 等）はCLAUDE.mdの対応表に従う
- `slug` は付けない（未公開状態。ページ生成は batch-generate で別途実行）
- `s: false` をデフォルトとして設定

### import-log.json の更新

`processed` 配列に追記する形式：

```json
{ "key": "インセプション_2010", "n": 2980, "dest": "movies", "imported_at": "2026-07-12" }
```

---

## Step 6: コミット（承認後のみ）

コミットメッセージ例：「フォームレビュー◯件インポート（映画◯件・別館◯件）」。push は報告後。

---

## 旧形式パース（移行期のみ・auto-detectで旧形式と判定された場合）

想定する列：タイムスタンプ / 映画タイトル / 公開年 / レビュー本文 / 監督 / 作曲家(劇伴) / 主題歌・挿入歌 / ジャンル / 備考

- タイムスタンプで `data/import-log.json` の `legacy_timestamps` と照合し、処理済みをスキップ
- 旧形式では【区分】列がないため、**デフォルトで「映画」扱い**とし、プレビューで明示する
- Step 2〜6は新形式と共通の処理を行う

---

## 運用メモ

- 推奨頻度：週1回程度まとめて
- インポート後の流れ：batch-generate でページ生成 → hub-generate でハブ更新
- Step D（旧形式コード削除）は、新フォームへの切り替えが安定した後に実施
