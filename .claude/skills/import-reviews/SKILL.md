# レビューインポートスキル（確定フォーマット / Google Forms CSV）

**CLAUDE.mdの作業フローを厳守。既存エントリーの上書きは絶対禁止。ユーザーが書いたレビュー本文は一字も変更しない。**

---

## 入力フォーマット（確定版）

Googleフォームの「タイトル＋レビュー」欄に以下の順で記入する。

```
オウチ de cinema 第◯◯作品    ← 無視行（あっても無くてもよい）

『 タイトル 』               ← 必須。英語・全角スペース込みで保存

公開年：2003                  ← 必須
監督：陣内孝則
劇伴：佐々木康詞、安藤日出雄
テーマ曲：ROCKERS/THe ROCKERS ← 「曲名 / アーティスト」順で保存
ジャンル：コメディ、音楽、青春

レビュー：                    ← 必須。この行以降がすべて本文
博多ロックコメディ映画。
コロン（：）が含まれても本文として扱う。
```

「区分」はフォームの別選択欄（ラジオボタン）で指定する。本文内には書かない。

複数レビューを1回の送信に含める場合は `===`（3文字以上）で区切る：

```
『 映画A 』
公開年：2022
レビュー：
本文A

===

『 映画B 』
公開年：2021
レビュー：
本文B
```

---

## 必須項目

| 項目 | 取得元 | バリデーション |
|------|--------|-------------|
| タイトル | 本文欄の `『 〜 』` 行 | 検出できない場合はエラー |
| 公開年 | 本文欄の `公開年：` 行 | 4桁数値以外はエラー（「2021年」は自動補正） |
| 区分 | フォームの選択欄（列マッピング参照） | 「映画」「別館」以外はエラー |
| レビュー本文 | `レビュー：` 行以降 | 行が存在しないまたは本文空はエラー |

---

## Step 0: 構造確認とCSV特定

1. movies.json の現在の件数と最大の n 値を確認
2. annex.json の現在の件数を確認
3. data/masters/ の3マスターを読み込む
4. CSVファイルのヘッダー行を読み、列名を確認する

---

## Step 1: パースと正規化

### 前処理

1. CSVから「タイトル＋レビュー」列と区分列を取得
2. 本文セル全体を `\n===+\n` でsplit → 複数エントリのリスト

### 各エントリのパース手順

#### ① タイトル抽出（優先順位）

1. `『 〜 』` パターンの行を検索 → `『』` 内をそのままタイトルとして使用（英語・全角スペース込み）
2. 上記なし → `タイトル：値` 形式の行でフォールバック
3. 両方なし → **エラー停止**

#### ② 本文切り出し

`レビュー：` で始まる行を検索 → その**次の行以降すべて**を本文とする。
`レビュー：` 行が存在しない場合は**エラー停止**。

#### ③ メタブロック

タイトル行の次の行 〜 `レビュー：` 行の前までをメタとして処理する。

各行を最初のコロン（全角`：`または半角`:`）で分割 → `キー: 値`

#### 無視行

- `第◯◯作品` パターン（正規表現: `/第\d+作品/`）
- `『』` で始まる行（タイトル取得済み）
- 空行

### 項目名マッピング（表記ゆれ吸収）

| 入力キー（前方一致） | 変換先フィールド |
|-------------------|--------------|
| 公開年 / 年 / リリース年 | `year` |
| 監督 | `director` |
| 劇伴 / 音楽 / 作曲家 / 作曲 / スコア | `composer` |
| テーマ曲 / 主題歌 / 挿入歌 / テーマ | `artists` |
| ジャンル / 分類 | `genre` |
| 主演 / 出演 / キャスト / その他の出演者 / 備考 | **無視**（警告ログに記録のみ） |

### 値の正規化

| フィールド | 処理 |
|-----------|------|
| year | `/(\d{4})/` で4桁数値を抽出（「2003年」→ 2003） |
| composer | 読点（、）・カンマで配列化 |
| genre | スラッシュ・カンマ・読点で配列化。中黒（・）は区切らない |
| artists | 「曲名 / アーティスト」順でそのまま保存 |

```javascript
parseComposer: raw.split(/[、,，]/).map(s => s.trim()).filter(Boolean)
parseGenre:    raw.split(/[\/,、，]/).map(s => s.trim()).filter(Boolean)
```

### バリデーション（エラー停止）

```
タイトル → 取得できない場合はエラー
公開年   → 未記入または4桁数値が取れない場合はエラー
区分     → 未取得または「映画」「別館」以外はエラー
レビュー：行 → 存在しない場合はエラー
本文     → 空またはスペースのみはエラー
```

エラー行は「エラーリスト」として一覧提示し、その行をスキップして残りを続行。
0件通過の場合は全体停止。

### 補助警告（エラーにしない）

区分=「映画」なのにタイトルまたは本文に「Season」「シーズン」「第\d+話」「S\dE\d」「連続ドラマ」「TVアニメ」を含む場合、プレビューに注記。

---

## Step 2: 区分の取得（フォーム列マッピング）

CSVの列名に応じて以下のルールで区分を判定する：

| 列名 | 判定 |
|------|------|
| `区分` | 値をそのまま使用（「映画」or「別館」） |
| `映画、またはレビュー作品 [TVドラマ、アニメ、その他の作品]` に値あり | → 別館 |
| `映画、またはレビュー作品` に値あり（TV列は空） | → 映画 |

---

## Step 3: auto-detect（3方式の切り分け）

CSVのヘッダー行の列名で判定する：

| 条件 | 方式 |
|------|------|
| 「タイトル＋レビュー」列がある | **現行確定フォーマット**（このドキュメントの主処理） |
| 「映画タイトル」列がある | **旧9列方式**（後述・後方互換） |
| 上記以外 + 本文に `【タイトル】` を含む | **旧ヘッダー方式**（後述・後方互換） |

---

## Step 4: 重複チェック（必須）

### インポート済み確認

`data/import-log.json` の `processed` 配列を検索し、`"key": "タイトル_公開年"` が存在すれば再取り込みスキップ。

### 重複チェック対象

| 区分 | チェック対象 |
|------|-----------|
| 映画 | movies.json + annex.json の両方 |
| 別館 | annex.json + movies.json の両方 |

タイトル一致（`t` フィールドに対象タイトルを含む、または対象タイトルが `t` を含む）で検出する。
一致した場合は「重複疑いリスト」として提示し、ユーザー判断を仰ぐ。

---

## Step 5: マスター照合

- 作曲家・アーティスト名をマスターと照合。表記ゆれはマスター表記に統一を提案
- 新規の名前はマスター追加案（slug付き）を提示し、承認後に追加
- ジャンルは genres.json のリスト外の値を検出したら報告（勝手に追加しない）

---

## Step 6: プレビューと承認

追加予定エントリーを表形式で提示：

| タイトル | 年 | 区分 | 監督 | 作曲家 | テーマ曲 | ジャンル | レビュー冒頭30字 |

あわせて報告する：
- 追加 ◯件 / 重複疑い ◯件 / エラー行 ◯件 / スキップ（インポート済） ◯件
- マスター新規追加 ◯件
- 警告（シリーズ疑い） ◯件

**ユーザー承認まで movies.json / annex.json には書き込まない。**

---

## Step 7: 書き込み

### 振り分け先

- 区分=「映画」→ movies.json に追加
- 区分=「別館」→ annex.json に追加

### n の採番

`max(movies.json最大n, annex.json最大n) + 1` から連番（n空間を共有して衝突を防ぐ）

### フィールド書き込み

- レビュー本文 → `d` フィールドへ（原文のまま、一字も変更しない）
- タイトル → `t` フィールド（英語・全角スペース込みでそのまま）
- 新フィールド（director / genre / music 等）はCLAUDE.mdの対応表に従う
- `slug` は付けない（未公開状態。ページ生成は batch-generate で別途実行）
- `s: false` をデフォルトとして設定

### import-log.json の更新

```json
{ "key": "ロッカーズ　rockers_2003", "n": 2980, "dest": "movies", "imported_at": "2026-07-12" }
```

## Step 8: コミット（承認後のみ）

コミットメッセージ例：「フォームレビュー◯件インポート（映画◯件・別館◯件）」。push は報告後。

## 旧形式パース（後方互換・移行期のみ）

### 旧9列方式（旧フォームCSV）

CSVヘッダーに「映画タイトル」列がある場合に使用。
タイムスタンプで `legacy_timestamps` と照合し処理済みをスキップ。
区分列がないためデフォルト「映画」扱い、プレビューで明示する。

将来削除予定：旧フォームデータの取り込み完了後に削除する。

### 旧ヘッダー方式（【タイトル】形式）

本文に `【タイトル】` を含む場合に使用。
`【キー】値` 形式でメタをパース。区分は `【区分】` ヘッダーから取得。

将来削除予定：新フォームへの移行が安定した後に削除する。
